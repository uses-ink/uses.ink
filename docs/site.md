# How this site is built

This site is the `docs/` folder of the repository, built by `ink` itself. It is the first site we
publish with the product we ship (roadmap M5), so any page that looks wrong here is a bug in
`ink` or in the page, never in a second tool. Decision 0120 has the reasons.

## What is published

`docs/ink.toml` is the site's configuration, the one file `ink` reads for a folder (decision 0018).
It does four things:

- **Selects.** A markdown file in `docs/` is published unless the file's `exclude` list names it.
  The list leaves out the working papers (`research/`), the pages for people who work on the code
  (`code.md`, `conventions.md`, `layout.md`, `libraries.md`, `workflow.md`, `release.md`), the owner's
  pages (`open.md`, `psl.md`) and `decisions.md`, a stub whose route would collide with the decisions
  index. No page carries a `publish` key: the list is the one place that says what is public, and
  `ink select` shows each page with the rung that decided it.
- **Orders.** `site.home` is `index.md`, a page written by hand, and `site.nav` is the list of header
  links, in the order written; the sidebar lists those pages first. `[folder."decisions"]` makes the
  decisions pages, not posts, though each has a `date` (decision 0140), and `weight` and `order` of a
  folder rule where it stands and how its pages are listed. The decisions index
  (`decisions/README.md`) is generated by `cargo xtask docs` and is the contents of the decisions.
- **Dresses.** `ink:theme-quiet` with two tokens: `look = "uses-ink"` wears the doodle design pass (decision
  0180): the palette and faces of `crates/core/token/token.toml` as `/look.css`, the stylesheet, the faces and
  the pen's marks as `/notebook.css`, `/fonts/*` and `/marks/*`, all files of the theme; and `navigation = "docs"`
  draws a sidebar of the folders, an outline of the page and previous and next links (decision 0141) in the same
  hand (decision 0182), with no script. A token the theme does not declare fails the build.

A page is public only through this list, so a new file in `docs/` is published the day it is
merged. Add it to `exclude` first if it is not for readers.

## How it is built

```
ink -C docs build --source folder -o <out>
ink -C docs build --check --source folder
```

`cargo xtask check sites` builds `ink`, builds every site fixture with `--check`, then builds this
site with `--check` twice, each time with an empty cache of its own. It fails when:

- a build says anything: a broken link (`link.target.missing`, `link.target.unpublished`), an
  element the format strips (`html.element.stripped`) or any other diagnostic, since the docs are
  expected to build with no warning;
- the native build and the build through the wasm components make different deploys;
- the two builds make different deploys, which is the reproducibility check: the deploy id is the
  hash of every file, so equal ids are equal bytes.

The `sites` job of `.config/farm.toml` lists `docs/**` among its inputs, so a change to a page
runs the check and a pass is reused only while the pages are the same. The separate `docs` stage
still checks the paths and decision citations of the prose and the front matter of the decisions.

A link to a page that is not published is a failure here, so a page that links to a contributor
page must name it as `code`, not as a link. Paths into the source (`crates/...`) are written as
code, since the site has no repository to link to.

## Publishing

Nothing deploys this site yet. Until `uses.ink` is live, `ink -C docs build -o <out>` writes the
site and `ink -C docs serve` serves it. Once the hosted service runs, the site is one more site on
it: a repository with `docs/` as its folder, built by the same builder as anyone's.

## Gaps

What a documentation site still lacks, written into the roadmap's M5:

- **No search.** Reader search is in the roadmap's later list.
- **No fold of the sidebar on a phone.** The three columns stack in reading order below 64rem, which
  works without script and is long on a page with many folders.
- **Not deployed.** Nothing publishes the site until `uses.ink` is live.

The look of the site is the design pass, not a second tool's: white paper, black pencil, Gaegu for names and
headings, Literata for the text, the red pen for uses.ink speaking. It has no dark scheme, since the design
has none. Nobody has looked at it in a browser on a farm host (none has one), so the stylesheet is checked
against the mock's CSS and the built HTML, and the owner's eye is the open check.

Closed by 0140 to 0142, and by 0180 to 0182 for the look: the sidebar and previous and next links, the uses.ink look through theme
tokens (T3), the outline of a page, the `page.kind` of a whole folder and the order of listings.
